# 暗线战争 · Shadowline War

独立实现的 Three.js 网页卡牌战场游戏。所有运行资源均已包含，运行时不需要互联网，也无需 npm install。

## 立即游玩

首选：直接双击 **暗线战争.html**，无需安装任何依赖，也无需终端。单文件和服务器版使用不同浏览器来源，因此存档彼此独立。修改源码后执行 `node build.mjs` 重建单文件。

也可以在 Windows 双击 **启动游戏.cmd**。它会寻找系统 Node.js 或本机 Codex 自带的 Node.js，在服务器就绪后打开浏览器。

其他平台：安装 Node.js 20+，在本目录运行 `node server.mjs`，打开 http://127.0.0.1:4173 。关闭终端即停止服务。端口被占用时可设置环境变量 PORT。

## 游戏内容

- 六张战场：双都对峙、裂谷防线、灰烬环岛，以及更复杂的东线纵深、半岛拉锯、法德西线。
- 人机对战：新兵与老兵两种策略风格；AI 不读取对方隐藏牌的点数、花色或洗牌状态。
- 同机双人对战：每次换人时遮蔽手牌，准备就绪后开始计时。**不是两台设备联网模式**。
- 初始策略三选一，13 种战役／交锋策略；公开战术商店每回合可购买一张。
- 战役夺取首都模式，以及不含地图、驻军、补给的经典模式。
- 30／60／120 秒或无限时、先行军团、随机种子、回合上限、策略开关。
- 暂停、规则手册、公开牌查询、音效开关、本浏览器自动存档。
- WebGL 不可用时降级为可操作的二维战术地图。

## 操作

地图阶段：点击目标据点。普通据点容量 3，中央城镇、峡谷中继和中央堡垒容量 4，首都容量 5；非首都至少一张明牌。己方据点可整编或花 3 补给快速换防。进攻敌方时，其固定驻军直接进入防线；对超过 3 张守军的据点可花 3 补给围城，封锁一张预备守军。

部署阶段：点击手牌依次循环 **明牌 → 暗牌 → 取消**。每方 1–3 张，至少 1 张明牌；进攻方明牌必须严格压过防守方。

对抗阶段：点击自己战线上的暗牌，选择翻开 1 或 2 张，或撤退。防守方平手即可赢，进攻方必须严格压过。详细规则和扩展说明均在游戏内“规则”。

## 原文歧义和本作扩展

仅参考用户指定的三个文件，没有读取或复用原仓库的其他逻辑或界面：

- https://github.com/lordstone/my_card_game/blob/main/instruction.md
- https://github.com/lordstone/my_card_game/blob/main/src/strategyCards/data/basic.json
- https://github.com/lordstone/my_card_game/blob/main/src/maps/data/duel_capital.json

交锋采用持续翻牌循环：首次进攻部署不会立即获胜。翻牌反超后，若对方仍有战线暗牌，轮到对方反击；仍被压制且有暗牌时继续翻牌或撤退。被压制方没有战线暗牌或撤退时才结算。平手由防守方占优，但不跳过另一方剩余暗牌的反击机会。闪电战与停火按各自效果结束交锋。

两张或三张明牌中出现两张同点数即为对子；三张同点数为三条。大小王是万能牌，会自动替代成能组成最强合法牌型的点数和花色。相同牌型与点数时天然组合胜万能牌组合；都使用一张王时大王胜小王。单张大王胜单张小王，但完整牌型仍优先于王的身份。A 不能环绕为 Q-K-A。

原 MVP 不定义地图、资源或特殊能力。战役模式扩展：每方开局首都部署三张暗牌，手中保留九张；普通据点容量三张，强化据点四张，首都五张，非首都至少一张明牌，首都可全暗。防守方公开牌超过三张时自动取最强三张计算；暗牌仍必须逐步翻开。驻军固定，守住后留守，攻下后由进攻战线接防。整编消耗地图行动，快速换防每回合可花三点补给一次；围城花三点补给封锁一张预备守军。每点产1补给、油田2，每2点补1张；交锋后补至12。医疗从己方公开牌恢复，起义生成额外A。完整细则见游戏手册。经典模式可关闭策略，单独体验54张牌的核心规则。

## 验证

`node tests/engine.test.mjs` 或 `npm test`。

已通过33组规则与事件测试：
- 全部24,804种三张牌组合的分类数量；
- 非法部署、严格比较、平手、防守翻牌、撤退、收牌和临时晋升清除；
- 13种策略的前置条件和效果，地图邻接、固定驻军、驻军明暗限制、整编、快速换防、首都胜利和牌数守恒；
- 超时行动、存档恢复与隐藏信息隔离；
- 144场跨地图、规则、策略开关、AI风格的完整对局，共8,440次合法行动。

已在 Chrome 中完成 8 组真实浏览器交互回归：AI 入侵与计时暂停、新牌展示、策略目标选择、驻军查看、同机交接保密、闪电战窗口、AI 反超后玩家继续翻牌、商店收展与策略悬停；覆盖 1440×900 桌面与 390×844 手机视口，无页面脚本错误或游戏页面滚动。测试覆盖这些场景，不代表绝对没有其他 bug。

浏览器测试导出 tests/browser.test.mjs 的 browserChecks(browser, url)，传入 Playwright 的 Chromium Browser 实例即可运行；需先启动本地服务器。独立 HTML 校验：npm run test:bundle。

## 项目结构

- `src/engine.js`：纯状态机、牌力、策略、AI；非法行动不改变原状态。
- `src/data.js`：地图、策略和选项。
- `src/app.js`：界面、选牌、暂停、计时、存档。
- `src/battlefield.js`：Three.js立体战区，故障时降级。
- `src/style.css`：战术界面与自适应布局。
- `vendor/`：Three.js r180官方构建及MIT许可证。
- `server.mjs`：仅监听127.0.0.1的无依赖静态服务器。
- `tests/engine.test.mjs`：规则与完整对局测试。

Three.js来源：https://github.com/mrdoob/three.js/tree/r180/build 。许可证保留于 vendor/THREE-LICENSE.txt。无遥测，无远程资源，无外部字体。存档属于本机浏览器的数据；更换端口或浏览器会使用独立存档。

## 1.1 试玩修复

入侵、占领、部署、翻牌、结算、补给和新牌均逐条展示，默认每条 3 秒；高级选项可改为 1 或 5 秒，也可点击继续。动画和暂停期间不消耗行动时限，AI 等待展示结束。新牌加入手牌后标记「新」。

进攻部署成功后，如持有交锋策略，会进入战术窗口，可先使用策略再让防守方反击。闪电战只允许己方占优时使用，修复原先只能被压制时使用、反而让对手获胜的问题。

驻军独立于手牌和公开牌堆计数。点击军团面板可查看各据点驻军；战斗动画会说明固定驻军进入防线及战后驻防结果。

## 1.1.1 翻牌反击修复

修复对手翻牌反超后立即判负的问题。有战线暗牌的一方会获得反击机会，双方可以连续反超；晋升、增援与侦察后的比较也使用相同流程。只有被压制方没有战线暗牌、撤退，或使用立即结算的策略时才结束交锋。

## 1.1.2 暗牌反击提示

己方可以看到暗牌牌面，但暗牌在翻开前不计入当前牌型。反击阶段，可翻开的战线暗牌现在带脉冲边框并标注“点击翻开”；选择后立即预览将形成的牌型，再点击确认。以两张明 K 加一张暗 K 为例，当前是“对子”，选择暗 K 后会预览“三条”，确认翻开后才正式反超。

## 1.1.3 两张明牌对子修复

修复两张同点数明牌被错误显示为高牌的问题。两张明牌同点数现在直接组成对子；第三张相同暗牌只有在正式翻开后才把对子升级为三条。

## 1.2.0 策略市场

战役模式新增三张公开策略市场。每个地图回合可购买一张，不消耗占领或进攻行动；购买后立即补充市场空位，每三轮整体刷新。普通支援价格为 4–5 点补给，强力战术为 6–8 点。每方最多持有三张，不能同时持有同名牌；新购策略在购买者下一个地图回合解锁，防止购买后立即爆发。已使用和被刷新的策略进入弃牌区，牌库耗尽时重新洗入。AI 会根据手牌、补给和局势采购，并通常保留至少 2 点补给。旧版本存档会自动补全市场状态。

## 1.3.0 固定驻军与单屏战场

每个据点最多三张固定驻军。普通据点至少一张明牌，首都允许三张全暗；开局双方首都各有三张暗牌。驻军被攻击时直接成为防守战线，守住后原地保留且已经翻开的牌维持公开；进攻胜利后，进攻战线成为新驻军。玩家可以消耗地图行动整编，或每回合花 3 点补给快速换防一次并继续行动。

战术商店改为可展开模块，持有策略改成图标坞，鼠标悬停或键盘聚焦时显示详情与可用原因。手牌改成重叠扇形牌桌布局；战场、手牌和情报栏在桌面与手机上固定于单个视口内。

## 1.3.1 据点操作栏修复

修复应用窗口在中等逻辑宽度下把目标栏改成纵向排列、又被固定高度裁切的问题。占领、整编驻军、快速换防、补给和结束行动按钮现在始终完整显示在目标栏内。

## 1.3.2 购买与补牌文案

普通牌操作由容易误读的“补给 · 2 点”改为“补充暗牌 · 2 补给”，并明确说明会消耗 2 点补给、从公共牌库随机抽取 1 张暗牌。策略商店的按钮同时直接显示购买价格、补给不足、已持有或本回合已购状态。

## 1.4.0 据点纵深防御

普通据点容量 3，三处强化据点容量 4，首都容量 5。超过三张的防守战线按已翻开牌中的最强三张计算，暗牌仍通过反击逐步翻开。进攻方可花费 3 补给发动围城，随机封锁一张第 4/5 位预备守军；守军守住后被封锁牌返回原驻军，攻方取胜时该牌回到防守方暗牌手中。

## 1.5.0 万能王牌

大小王改为万能牌，会自动寻找当前可组成的最强合法牌型。例如两张 3 加小王组成三条 3，同花 10、J 加王组成 Q 高同花顺。相同牌型与点数时天然组合优先；双方都依赖一张王时大王优先。单张大王仍胜单张小王，牌型等级始终优先。

## 1.6.0 历史战区拓扑

新增三张以真实战区地理关系为灵感的复杂地图：14 点“东线纵深”沿北部港口、中部铁路枢纽和南部油区展开；11 点“半岛拉锯”由狭长海岸、山地走廊与首尔枢纽连接；12 点“法德西线”提供低地迂回、阿登突破和南部山地路线。港口、山地、工业油区、强化城市与首都使用不同图标和 3D 地标。地图用于抽象策略玩法，不按具体历史时间点复刻兵力或国界。

## 1.7.0 iPad 战场与地图交互

修复带新牌展示的策略事件因卡牌容器未闭合而破坏整个快报布局的问题。游戏界面改用固定三行视口结构，浏览器工具栏改变可用高度时，地图自动收缩并始终为底部手牌和战术栏预留空间；已实测 iPad 横屏 1024×768 与竖屏 768×1024 均无页面溢出。

战役顶栏明确显示每轮剩余的 1 点主要行动。占领、进攻、整编或结束行动消耗该点；购买策略、补充暗牌和快速换防继续按各自限制执行。地图新增鼠标、触控拖动、滚轮与双指缩放，以及放大、缩小、复位按钮。Three.js 地标、拓扑线路和可交互据点统一使用最终投影坐标，并作为同一个视图同步平移缩放。

### 1.7.1 手牌排序切换

手牌区新增“点数／花色”切换。点数模式按牌点从小到大排列，同点数按花色排列；花色模式先按黑桃、红桃、梅花、方片分组，各组内按点数从小到大排列，大小王列在最后。排序只改变显示，不修改战局状态或存档中的牌序。

## 1.8.0 战场态势可视化

朝鲜半岛等南北跨度明显大于东西跨度的地图自动启用更接近垂直俯视的专用相机，并适当扩大东西方向间距，完整保留南北两端边距。复杂地图隐藏据点上的重复容量文字，将空间留给名称和军情。

地图据点现在直接展示微型驻军牌：明牌显示牌面，自己的暗牌显示带暗部署质感的牌面，敌方暗牌只显示统一牌背。放大地图时据点面板和微型牌执行反向缩放，地形与路线被放大的同时，操作目标维持稳定尺寸，减少相互遮挡。

### 1.8.1 缩放文字清晰度

据点面板从地图的 GPU 缩放层中独立出来。地形和路线继续平移缩放，据点则根据相同视图参数重新计算屏幕坐标并始终以原生像素渲染，避免反向缩放造成文字和牌面二次采样模糊。

## 1.9.0 自适应牌库与王牌视觉

高级选项新增“公共牌库”：可以跟随地图，或固定为 1 副／2 副。跟随地图时，5–11 个据点使用 54 张牌，12 个以上据点使用 106 张牌。两副模式包含两套普通牌但只保留唯一一对大小王，避免万能牌数量翻倍；第二套普通牌与策略生成牌均使用独立 ID，牌数守恒校验覆盖两种规模。

小王使用银色金属牌面，大王使用金色牌面和暖色辉光；微型驻军牌同样显示对应金银等级。敌方未揭示的王牌仍保持统一牌背，不会泄露隐藏信息。

### 1.9.1 全局版本标识

所有界面的右下角固定显示低对比度版本号，并适配 iPad 安全区域。版本标识不接收点击，也不会随菜单、事件、暂停或结算界面切换而消失。

### 1.9.2 紧凑策略商店

策略市场从地图下方的整行栏位移动到右侧“战术指令”旁的小型商店按钮。按钮显示当前市场的三张牌数量，点击后仍打开原有的策略市场窗口并保留购买、补货、限制和解锁规则，战场地图因此获得完整高度。

### 1.9.3 反击说明与 iPhone 窄屏

反击阶段明确显示当前只比较已翻开的明牌；若双方高牌相同，第二、第三张明牌仍依次比较。暗牌只有点击翻开并确认后才参与牌型和胜负计算。新增这一精确比较的规则回归测试。

对 320–390px 宽度进一步压缩了行动栏、战线牌、据点按钮、菜单和弹窗边距，保留单屏作战结构并适配 iPhone SE 到标准 iPhone 宽度。
